# v2.3.13 — Synthesis speed Phase 3 (merge input/output optimization)

Production release for **Phase 3 merge optimization**: tighter partial summaries, optional Gemini compaction before Sonnet merge, Anthropic prompt caching on merge input, and opt-in multi-segment planning for large single-pass jobs. Builds on v2.3.12 Phase 2 (streaming final merge).

**Operating mode unchanged:** browser tab open, background worker off, Opus audit off.

---

## Highlights

- **Table-shaped partial synthesis prompt** — denser Gemini segment output (chain rows, defects, running balance)
- **Gemini compaction pass** — when ≥6 segments or merge input ≥40k tokens, Flash compacts summaries before Sonnet final merge
- **Anthropic prompt caching on merge** — segment summary block cached when ≥1024 tokens; `synthesis_prompt_cache_usage` log event
- **Opt-in large-job multi-segment planning** — `SYNTHESIS_LARGE_JOB_MULTI_SEGMENT` (default off) forces Gemini partials instead of one Sonnet pass on bulk jobs

---

## Phase 3.1 — Tighter partial synthesis prompt

### Change
`PARTIAL_SYNTHESIS_PROMPT` now requires strict table output:

- `## CHAIN ROWS` — pipe table per instrument
- `## DEFECTS` — pipe table
- `## RUNNING BALANCE` — pipe table

No preamble prose between sections. Final ownership table remains deferred to Sonnet merge.

### Effect
Shorter, denser partial summaries → smaller Sonnet merge input and faster time-to-first-token on final merge.

---

## Phase 3.2 — Gemini compaction before final merge

### When
`SYNTHESIS_COMPACTION_ENABLED` (default **on**) and either:

- Segment count ≥ `SYNTHESIS_COMPACTION_MIN_SEGMENTS` (default **6**), or
- Estimated merge input ≥ `SYNTHESIS_COMPACTION_MIN_MERGE_TOKENS` (default **40000**)

### Flow
```text
N partial summaries → Gemini Flash compaction (COMPACTION_SYNTHESIS_PROMPT)
  → single compact scaffold → Sonnet final merge (streaming when enabled)
```

Warning flag: `merge_compaction_applied`. Log event: `synthesis_merge_compaction_start`.

---

## Phase 3.3 — Prompt caching on merge user content

### Change
Final Sonnet merge requests wrap the segment summary block in Anthropic `cache_control: { type: 'ephemeral' }` when content ≥1024 tokens (`SYNTHESIS_MERGE_CACHE_MIN_TOKENS`).

Structured log when cache is used:
- `synthesis_prompt_cache_usage` — includes `cacheReadInputTokens`, `cacheCreationInputTokens`

Benefit: merge retries and follow-ups can hit cache on repeated segment prefix.

---

## Phase 3.4 — Large-job multi-segment planning (opt-in)

### Problem
Jobs planned as a single segment send all raw abstracts to Sonnet with no Gemini compression.

### Change
When **`SYNTHESIS_LARGE_JOB_MULTI_SEGMENT=true`** and abstract count ≥ `BULK_JOB_MIN_ABSTRACTS`, replan with standard chunk size (bypass bulk 200-doc segments) to force multiple Gemini partial passes.

Opt out: **`SYNTHESIS_FORCE_SINGLE_PASS=true`**

**Not enabled in production release deploy by default** — enable deliberately after validating quality on golden jobs.

## Production configuration (API service)

| Variable | Value | Notes |
|----------|-------|-------|
| `OPUS_AUDIT_ENABLED` | `false` | Required |
| `SYNTHESIS_CONCURRENCY` | `8` | Parallel Gemini partials |
| `SYNTHESIS_BATCH_LIMIT` | `8` | Segments per process kick |
| `SYNTHESIS_STREAM_ENABLED` | `true` | Stream final merge (Phase 2) |
| **`SYNTHESIS_COMPACTION_ENABLED`** | **`true`** | **New default in v2.3.13** |
| `SYNTHESIS_COMPACTION_MIN_SEGMENTS` | `6` | Compaction segment threshold |
| `SYNTHESIS_COMPACTION_MIN_MERGE_TOKENS` | `40000` | Compaction input threshold |
| `SYNTHESIS_LARGE_JOB_MULTI_SEGMENT` | *(unset / false)* | Opt-in only — not set on deploy |
| `SYNTHESIS_MAX_TOKENS` | `5000` | Final Sonnet output cap |
| `SYNTHESIS_PARTIAL_MAX_TOKENS` | `4000` | Partial summary cap |
| `ABSTRACTION_ESCALATION_ENABLED` | `false` | Skip Sonnet re-reads |

**Worker service (unchanged):** `WORKER_DISABLED=true`, scale-to-zero.

## Ops checklist after deploy

1. Run a 200+ doc job; compare `synthesis_merge_complete.inputTokens` to pre-v2.3.13 baseline
2. Confirm `merge_compaction_applied` appears only on jobs with ≥6 segments or very large merge input
3. On merge retry, check for `synthesis_prompt_cache_usage` with `cacheReadInputTokens > 0`
4. Do **not** enable `SYNTHESIS_LARGE_JOB_MULTI_SEGMENT` until golden-job quality sign-off

## What's next

All three synthesis speed phases (0–3) are now shipped. Future work is quality/ops tuning and optional enablement of `SYNTHESIS_LARGE_JOB_MULTI_SEGMENT`.
