## Changes

- **Worker drain auth:** `POST /internal/drain` requires header `X-Internal-Drain-Token`, compared to `INTERNAL_DRAIN_TOKEN` with `secureCompare`. Production (`NODE_ENV=production` or Cloud Run `K_SERVICE`) returns 401 and does not drain when the token is unset. Outside production, an unset token still allows a local drain; a configured token is required in every environment. `/healthz` stays unauthenticated. Cloud Run IAM remains the outer gate (`--no-allow-unauthenticated`).
- **Scheduler:** `docs/worker-synthesis-scheduler-runbook.md` sets `INTERNAL_DRAIN_TOKEN` on the worker and sends the same value as `X-Internal-Drain-Token` from Cloud Scheduler, beside the OIDC bearer token. Do not put the secret in `Authorization`.
- **Docs:** README rewritten to match the code (shared GCS rate-limit state, no claimed `GEMINI_THINKING_LEVEL` default, table of synthesis overrides the release workflow sets). #82 restored the phrases `test/release.test.js` asserts after that rewrite dropped them. AGENTS.md now matches the current models, test chain, and auth rules, including the drain check.
