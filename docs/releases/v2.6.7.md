## Changes

- **OCR comparison lab:** `/ocr-compare.html` accepts one PDF or image, displays the source beside both model outputs, and runs the configured Gemini 3-series baseline (default `gemini-3.1-flash-lite`) and `gemini-3.8-flash` in parallel.
- **Visual inputs:** PDFs are rendered locally into page images before comparison; hidden searchable text layers are not passed to either model. Pinned PDF.js assets are served through an explicit local allowlist.
- **Review and reporting:** show extracted-field differences, model/provider/thinking settings, timing, token usage, estimated direct-Gemini cost, and independent errors. Downloadable JSON reports exclude source images and credentials. Differences are review cues, not accuracy scores.
- **Isolation and opt-in:** the API requires the existing app password and `OCR_COMPARE_ENABLED=true`. It does not create durable title jobs, save lab documents or abstracts, invoke synthesis or escalation, automatically retry calls, or change production model defaults. Each comparison makes two potentially billable direct-Gemini calls. Limits are 10 pages and 12 MB of rendered image data, with one comparison at a time per server instance.
- **Synthetic title-chain fixture:** `scripts/generate_chain_pdf.py` generates a connected searchable chain of title and Markdown/JSON answer keys for Section 14, Block 57, Reeves County, Texas, from an 1884 patent through a 2014 assignment. It includes probates, heirship affidavits, NPRI/ORRI interests, lease expiration, corrections, corporate/trust transfers, liens/releases, and pooling. Generated files remain in git-ignored `scripts/sample-docs/`. The standalone generator requires Python and ReportLab; it is not part of the server's execution path.

## Verification and rollout

- Clean `npm ci` and the full `npm test` chain passed under Node 22, including the 7 release checks and 24 OCR route/UI tests. Existing tests are unchanged in this release metadata update.
- Automated OCR tests use provider fixtures; they prove request handling, concurrency, visual payloads, authentication, error isolation, and UI/report behavior, not live OCR accuracy.
- The tag-triggered release workflow runs tests, builds one immutable image, deploys the worker and API from that same image digest, verifies release parity and API health, and creates the GitHub Release.
- Preserve the API service's configured `OCR_COMPARE_ENABLED=true`; the deployment uses `--update-env-vars`, not a replacement environment. The worker does not need this flag. Open `/ocr-compare.html` after deployment and use the existing app password.
- No live paid model calls are part of this release verification. Representative title documents and provider access are required for a real quality comparison.
