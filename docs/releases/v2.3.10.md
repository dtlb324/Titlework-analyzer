# v2.3.10 — Synthesis speed Phase 0 (browser-driven ops)

Production release focused on **faster, observable server-side synthesis** while keeping the background worker and Opus audit **disabled** per current ops policy.

## Highlights

- **Phase 0 ops runbook** for browser-driven jobs (tab must stay open)
- **Production env defaults** applied on API deploy for synthesis speed tuning
- **Structured Cloud Logging** for merge duration, segment counts, and browser-fallback detection
- **Keep-tab-open UI banner** during server abstraction and synthesis
- **Design spec** documenting the full synthesis speed roadmap (Phases 1–3 deferred items included)

## Production configuration (API service)

Set automatically on each release deploy:

| Variable | Value | Purpose |
|----------|-------|---------|
| `OPUS_AUDIT_ENABLED` | `false` | No second Opus pass after Sonnet merge |
| `SYNTHESIS_CONCURRENCY` | `8` | More parallel Gemini partial segments (max 16) |
| `SYNTHESIS_MAX_TOKENS` | `5000` | Slightly shorter final Sonnet output |
| `SYNTHESIS_PARTIAL_MAX_TOKENS` | `4000` | Smaller partial summaries → lighter merge input |
| `ABSTRACTION_ESCALATION_ENABLED` | `false` | Skip extra Sonnet re-reads on low-confidence abstracts |

**Worker service (unchanged):** `WORKER_DISABLED=true`, scale-to-zero, `OPUS_AUDIT_ENABLED=false`.

Jobs continue to run via **API kicks + browser polling** while the tab is open. Enable the worker later with `WORKER_DISABLED=false` when unattended processing is needed.

## Observability

New structured JSON log events (filter on `jsonPayload.event` in Cloud Logging):

| Event | When |
|-------|------|
| `synthesis_merge_complete` | Final title opinion saved — includes `segmentCount`, `synthesisDurationMs`, `inputTokens`, `outputTokens`, `warningFlags`, `synthesisDriver: server` |
| `synthesis_batch_complete` | Each `/synthesis/process` batch finishes |
| `synthesis_driver_browser_fallback` | Browser saved result via POST `/result` — **should not appear** on healthy durable jobs |

Use `synthesis_merge_complete` logs to establish P50 merge-duration baselines before Phase 1/2 work.

## Product decisions (unchanged)

- **Opus audit:** off in production; not scheduled
- **Background worker:** off for now; browser-driven mode is intentional

## Ops checklist after deploy

1. Run a representative job with the **tab open** through final merge
2. Confirm `synthesis_merge_complete` appears in logs
3. Confirm **no** `synthesis_driver_browser_fallback` events on durable server-abstraction jobs
4. If opinions look truncated, raise `SYNTHESIS_MAX_TOKENS` toward `6000` in Cloud Run console
