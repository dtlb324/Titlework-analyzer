# v2.6.20 — Truncated-output fail-closed fixes and README accuracy

Patch release covering every commit since v2.6.19: PR #127 (November bug hunt), PR #128 (README), and the release metadata commit.

## Included changes

### Fixes (#127)

- **Worker upload gate:** the drain no longer abstracts or synthesizes jobs still in `created`/`uploading`. Previously the rollup moved the job past `ready`, `finalize-uploads` returned 409, and the page started a second paid browser run whose result the worker later deleted.
- **Truncated abstracts:** `runModelAbstraction` now throws `output_truncated` on a `max_tokens` stop instead of saving a cut-off abstract as completed. It is not retried at the same limit; multi-page PDFs reuse the existing page split.
- **Batch abstract mapping:** `parseBatchAbstracts` maps parsed abstracts to chunks only when the array length matches. A mismatched array leaves every slot empty so each chunk is re-abstracted on its own, instead of storing one file's facts under another.
- **Browser run truncation:** `callBackend` keeps `stop_reason`, so a `max_tokens` synthesis is no longer saved as a complete opinion. Multi-file abstraction batches split in half; synthesis and follow-ups fail closed.
- **Server follow-up truncation:** `answerFollowupQuestion` returns 502 on a `max_tokens` reply before `appendFollowupMessage`, matching `callSynthesisModel`, so a truncated answer is not stored.
- **Malformed job path:** a job path that `decodeURIComponent` cannot decode now returns 400 before auth instead of 500, and only 5xx responses are logged as `cloud_run_server_error`.
- Regression tests pin each of the above.

### Documentation (#128)

- README setup and environment-variable facts now match the code: `SYNTHESIS_MAX_TOKENS` caps single-pass opinions and follow-ups, the multi-segment merge uses `SYNTHESIS_MERGE_MAX_TOKENS`, and the synthesis merge-lease variables apply only when the workflow lease argument is omitted. The auth link points at the service-account section.

### Release metadata

- `package.json`, both root lockfile versions, and these notes move to 2.6.20.

## Rollout

- No environment variable or schema change is required.
- Behavior change: truncated model output (abstracts, browser synthesis, follow-ups) now fails or splits instead of being saved. Jobs that previously "completed" with silently truncated text may now show a failure or warning.
- The release workflow deploys the worker and API from one immutable image digest, verifies version and service parity, and creates the GitHub Release.
