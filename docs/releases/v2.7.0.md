# v2.7.0 — PDF accuracy: visual isolation, batch escalation and high-DPI re-reads

Minor release covering all commits since v2.6.23, plus release metadata. The published release lists the complete commit range.

## Included pull requests

| PR | Change |
| --- | --- |
| #147 | Admit large PDFs so Files API delivery or page-range splitting can handle them. |
| #149 | Run visual PDFs solo, key batch output by document, and request high media resolution on Gemini visual PDFs. |
| #150 | Escalate flagged batch chunks with quality checks; separate absent fields from ILLEGIBLE; renew chunk leases before paid calls. |
| #151 | Re-read illegible PDFs as high-DPI page images rendered in the browser. |

## Changes

### Features

- **High-DPI re-read (#151):** PDFs whose abstracts flag illegible fields get a "Re-read as high-DPI page images" action. Pages are rendered locally (`public/pdf-raster.js`) and sent as image blocks (`rendered_images` delivery) with an envelope size check; rendered chunks run solo. The abstraction prompt now marks unreadable values as `ILLEGIBLE - VERIFY MANUALLY`. Intake warns when a PDF is 15+ pages and may bundle several instruments. CSP allows `wasm-unsafe-eval` and blob workers for the local renderer.
- **Batch escalation with quality checks (#150):** escalation now runs on batched abstracts, not only solo calls; each flagged chunk re-reads once via its own visual request. Deterministic quality reasons (`validateAbstractQuality`) feed the triggers (CSV chunks skipped), escalation failures are logged as redacted structured warnings, and lease-guarded persistence falls back to solo without re-firing escalation.
- **Gemini media resolution (#149):** direct Gemini calls with PDF or image parts send `generationConfig.mediaResolution` (default high; configure with `GEMINI_PDF_MEDIA_RESOLUTION`, `off`/`false` to omit).

### Behavior changes

- Scanned, stamped, image-backed and large PDFs and images run solo instead of in multi-document batches; only text-extracted PDFs and CSVs are batched. `ABSTRACTION_BATCH_MAX_DOCS` default drops from 24 to 6.
- Batch responses are keyed `{docIndex, abstract}`; mismatched or duplicate indexes fall back to solo. Documents are wrapped in START/END markers.
- `ABSTRACTION_PDF_TEXT_STRICT` is on by default (set `false` to disable).
- PDF splitting uses a shared page-range helper with a one-page overlap for 4+ pages.
- Release workflow synthesis token defaults raised to `SYNTHESIS_MAX_TOKENS=8000` / `SYNTHESIS_PARTIAL_MAX_TOKENS=5000`.

### Fixes

- Large multi-page PDFs are admitted up to the upload limit (single pages up to the Files API maximum) instead of failing with `payload_too_large` before the split fallback (#147).
- Absent fields are kept distinct from ILLEGIBLE, and escalation triggers are scoped to key fields (server and browser) (#150).
- Quality checks no longer escalate clean abstracts: explicit "not applicable" accepted where the instrument plausibly lacks the field, unknown heirs kept as party names, role tags and capacity clauses normalized in name matching, two-digit-year dates matched, decoration regexes bounded (#150).
- Chunk leases are renewed before each paid call (batched into one query per round, including persist-fallback chunks); work stops when a lease is lost (#150).

### Tests and housekeeping

- Pinned fetch ceilings for large PDFs and images; labeled clean/defective abstract corpus; async Gemini request tests awaited.
- Added `docs/pdf-accuracy-optimization-plan.md`; restored stray `.DS_Store` changes.

### Release metadata

- Update the package and root lockfile versions to 2.7.0.
