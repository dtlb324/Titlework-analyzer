# v2.6.16 — Job-store Postgres fixes and CI hardening

Patch release covering every commit since v2.6.15, including PR #103, PR #104, and the release metadata commit.

## Included changes

## Job-store and workflow repairs (#104)

- Cast `workerId IS NULL` guards to `::text` in chunk retry, fail, split-supersede, and split-create paths so Neon/Postgres can type the parameters. Retryable and terminal chunk failures no longer throw from the error handler and leave chunks stuck in `processing`.
- Reset `abstraction_attempts` and `abstraction_reclaims` when retrying failed chunks so "Retry N failed" and per-chunk retry get a fresh attempt budget instead of immediately failing as `max_attempts`.
- Keep zero `payloadBytes` / `latencyMs` on continuation import (`?? 0`) so reused abstracts do not hit NOT NULL violations mid-import. Deduplicate repeat imports by per-source-chunk fingerprint instead of `chunk_order = orderOffset`.
- Accept UUID hyphens in import-continuation job ids (`job_` + `randomUUID()`), so "Add documents" can import prior abstracts instead of falling back to in-browser synthesis.
- Leave job status alone during continuation import; skip already-abstracted imported chunks in finalize-uploads so the new job can upload, finalize, abstract, and synthesize correctly.
- Resume synthesis segment attempts from the claimed `attempt_count`, fail reclaims past the max as `max_attempts` without calling the model, and reset `attempt_count` on "Retry synthesis". Stops unbounded Sonnet retries on a single-pass segment.
- Refuse cancel once a job is `complete` (409), and guard the cancel UPDATE so a race with the final merge cannot hide a paid-for opinion.
- Refuse per-chunk retry on a canceled job (409) so cancel cannot still pay for an unused abstract.
- Keep the PATCH blobUrl storage test off live GCS by injecting a stub rate-limit backend while `GCS_BUCKET` is set for the test.

## CI and supply-chain hardening (#103)

- Weekly grouped Dependabot for npm, GitHub Actions, and Docker.
- Checksum-pinned gitleaks scan on pull requests; secret scan drops checkout credentials and falls back to the default branch when a push has no usable before commit.
- Third-party actions pinned to commit SHAs; workflow tokens stay `contents: read` except jobs that create a GitHub Release or mint a Google Cloud identity token.
- Tests workflow also runs on pushes to `Main`.
- `github-release` sets `GH_REPO` so release creation works outside a checkout.

## Verification and rollout

- Both PRs landed on `Main` after their own test coverage. #104 was verified against real Postgres over HTTP for import, upload, finalize, server abstraction, and server synthesis.
- No environment variable change is required for these repairs. Existing `APP_PASSWORD`, database, bucket, and model settings are unchanged.
- The release workflow deploys the worker and API from one immutable image digest, verifies version and service parity, and creates the GitHub Release.
