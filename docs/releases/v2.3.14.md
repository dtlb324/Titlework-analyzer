# v2.3.14 — Deployed version in app header

Patch release: the web app header shows the **GitHub release tag** currently running in production, directly under **Title Research Tool**.

---

## Highlights

- **Header version label** — loads `release.version` from `/api/healthz` on page load (e.g. `v2.3.14`)
- **Automatic on deploy** — release workflow already sets `RELEASE_VERSION` from the tag; no manual frontend bumps
- **Local dev** — `npm start` shows `v{package.json}` via the same health endpoint when `RELEASE_VERSION` is unset

---

## UI

Under the tagline **Title Research Tool**, a muted line displays the deployed tag. Compare it to your latest GitHub release to confirm you are on the current build.

### Files

- `public/index.html` — `#appVersion` element, `loadAppVersion()`, styling
- `test/app.test.js` — asserts health endpoint wiring

---

## Deploy / verify

Same tag-driven release as prior versions:

```bash
VERSION="v$(node -p "require('./package.json').version")"
git tag "$VERSION"
git push origin "$VERSION"
```

After deploy, confirm `/api/healthz` and the header both report `v2.3.14`.
