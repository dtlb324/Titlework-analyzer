# v2.3.12 — Synthesis speed Phase 2 (stream final opinion)

Production release for **Phase 2 perceived-latency optimization**: the final Sonnet merge streams text to the browser while generation continues server-side. Builds on v2.3.11 Phase 1 (batch limit + fallback visibility) and v2.3.10 Phase 0 (env tuning, metrics, keep-tab-open UI).

**Operating mode unchanged:** browser tab open, background worker off, Opus audit off.

---

## Highlights

- **`SYNTHESIS_STREAM_ENABLED=true`** on API deploy — final Sonnet merge uses Anthropic streaming
- **`GET /api/jobs/:id/synthesis/preview`** — poll buffer `{ text, complete, bytesReceived }` during merge
- **UI streaming preview** in the progress card while `mergeInProgress`
- **Validation unchanged** — preview is ephemeral; `job_results` is written only after `validateFinalOpinion` passes
- **New metrics** — `synthesis_merge_stream_delta`, plus `streamed` / `timeToFirstDeltaMs` on `synthesis_merge_complete`

---

## Phase 2.1 — Stream final merge

### Problem
After all Gemini partial segments finish, users waited on a blank screen while Sonnet generated the full title opinion (often 30–90+ seconds). Total generation wall-clock is unchanged; only **perceived** latency improves.

### Change
When `SYNTHESIS_STREAM_ENABLED=true` and the server holds the merge lease:

1. Anthropic Messages API is called with `stream: true`
2. Text deltas are buffered in Postgres (`analysis_jobs.synthesis_preview_*` columns), throttled ~250ms
3. The browser polls `/synthesis/preview` during `mergeInProgress` and renders a draft opinion card
4. On stream completion, `validateFinalOpinion` runs on the full buffer
5. Valid opinions are saved via `saveJobResult`; invalid previews are discarded (not persisted as final)

Partial segment synthesis (Gemini) and tree-merge intermediate steps remain non-streaming. Browser synthesis fallback is out of scope for this release.

### API

| Route | Method | Response |
|-------|--------|----------|
| `/api/jobs/:id/synthesis/preview` | GET | `{ preview: { text, complete, bytesReceived, updatedAt? }, requestId }` |

Poll during `status.mergeInProgress === true`. Preview is cleared when the final result is saved or validation fails.

### UI

During `pollServerSynthesis`, when segments are complete and the final merge is running:

- Progress label: *Final title opinion merge in progress (streaming preview below)...*
- A **Draft title opinion (streaming preview)** card appears below the progress list
- Text updates as `/synthesis/preview` returns new bytes; card hides when merge completes

### Files
- `api/_lib/anthropic-stream.js` — Anthropic SSE parser (`consumeAnthropicMessageStream`)
- `api/_lib/model-client.js` — `invokeAnthropicModelStream()`
- `api/_lib/synthesis.js` — `synthesisStreamEnabled()`, preview writer, merge streaming in `callSynthesisModel`
- `api/_lib/jobs.js` — `synthesis_preview_*` columns, `setSynthesisPreview` / `getSynthesisPreview` / `clearSynthesisPreview`
- `api/jobs/[...path].js` — preview route handler
- `public/index.html` — `fetchServerSynthesisPreview`, `renderSynthesisPreview`, preview card CSS
- `README.md` — `SYNTHESIS_STREAM_ENABLED` documented

## Production configuration (API service)

Set automatically on this release deploy (cumulative with v2.3.10–v2.3.11):

| Variable | Value | Notes |
|----------|-------|-------|
| `OPUS_AUDIT_ENABLED` | `false` | Required — do not enable |
| `SYNTHESIS_CONCURRENCY` | `8` | Parallel Gemini partial segments |
| `SYNTHESIS_BATCH_LIMIT` | `8` | Segments per process kick |
| **`SYNTHESIS_STREAM_ENABLED`** | **`true`** | **New in v2.3.12** — stream final merge |
| `SYNTHESIS_MAX_TOKENS` | `5000` | Final Sonnet output cap |
| `SYNTHESIS_PARTIAL_MAX_TOKENS` | `4000` | Partial summary cap |
| `ABSTRACTION_ESCALATION_ENABLED` | `false` | Skip Sonnet re-reads on low-confidence abstracts |

**Worker service (unchanged):** `WORKER_DISABLED=true`, scale-to-zero, `OPUS_AUDIT_ENABLED=false`.

**Local / dev default:** `SYNTHESIS_STREAM_ENABLED` is off unless set — streaming is opt-in outside production release deploy.

## Observability

| Event | When |
|-------|------|
| `synthesis_merge_stream_delta` | First streamed delta from final merge — includes `timeToFirstDeltaMs`, `outputBytes` |
| `synthesis_merge_complete` | Final opinion saved — now includes `streamed` and `timeToFirstDeltaMs` when applicable |
| `synthesis_batch_complete` | Each `/synthesis/process` batch (unchanged from v2.3.11) |
| `server_synthesis_fallback` | Browser POST `/result` after server synthesis failed (unchanged) |

**Healthy durable jobs:** draft preview visible during merge; final `synthesisDriver: server`; no fallback log events.

## Ops checklist after deploy

1. Run a multi-segment job (~200+ docs) with tab open; confirm draft opinion text appears within a few seconds of segment completion
2. Check `synthesis_merge_stream_delta` logs for `timeToFirstDeltaMs` on large jobs (target &lt; 5s)
3. Confirm `synthesis_merge_complete` shows `streamed: true` on server-synthesized jobs
4. Verify final saved opinion matches pre-streaming quality (sections present, no truncated preview persisted)
5. Confirm **no** `server_synthesis_fallback` on normal durable runs
